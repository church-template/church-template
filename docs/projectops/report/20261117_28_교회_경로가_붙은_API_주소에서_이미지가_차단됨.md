# 교회 경로가 붙은 API 주소에서 이미지가 차단됨

## 개요

`client/next.config.ts`가 `next/image`가 허용할 미디어 주소를 `new URL("/api/media/**", API주소)`로 만들고 있었다. 앞에 `/`가 붙은 경로를 주면 API 주소의 경로(`/church/<교회키>`)가 버려져서, 공유 서버를 쓰는 교회는 실제 사진 주소와 허용 주소가 맞지 않았다. 은샘 프론트에서 이미 고친 방식을 그대로 가져와 고쳤다. [PR #29](https://github.com/church-template/church-template/pull/29)로 `develop`에 병합하고, 릴리스 PR #30으로 `main`에 나가 `v0.6.1`로 확정됐다.

## 변경 사항

- `client/src/lib/mediaRemotePattern.ts`(신규), `mediaRemotePattern.test.ts`(신규): API 주소 끝의 `/`를 지우고 `/api/media/**`를 이어 붙여 교회 경로를 보존한다. API 주소가 없으면(CI 빌드) 원격 패턴이 없다. 은샘 파일 그대로.
- `client/next.config.ts`: `remotePatterns`를 이 함수로 만든다. `next.config.ts`는 경로 별칭(`@/…`)을 쓸 수 없어서 함수를 상대 경로로 불러오고, 함수는 다른 모듈에 의존하지 않는다.

## 주요 구현 내용

- **증상:** API 주소가 `https://api.example.com/church/<교회키>`이면 허용 주소가 `https://api.example.com/api/media/**`가 되어 실제 사진 주소와 맞지 않았다. 로그인한 사람만 보는 화면(갤러리 앨범 카드·사진 목록, 관리 미디어 선택 창·라이브러리)이 오류 화면으로 바뀐다. 공개 페이지는 영향이 없다. 공유 서버를 쓰는 새 교회는 처음 미디어 관리 화면을 여는 순간 만난다.
- **확인:** Next의 실제 허용 검사(`hasRemoteMatch`)에 같은 사진 주소를 옛 방식과 새 방식으로 넣어 비교했다.

  | 방식 | 내 교회 사진 | 다른 교회 사진 |
  |---|---|---|
  | 옛 방식 | 차단 (문제 재현) | 차단 |
  | 새 방식 | 허용 | 차단 |

  새 방식은 다른 교회의 사진을 계속 막는다(교회 경로를 보존하므로 `/church/other/…`는 허용되지 않는다).
- 검사: 타입 검사, 린트(오류 0), 교회 경로가 붙은 API 주소로 빌드 통과. 테스트 1155개 중 1154개 통과(실패 1개는 이번 변경과 무관하게 원래 실패하던 `SymbolismList`).
- **릴리스:** `develop → main` 릴리스 PR #30이 자동 병합되어 `v0.6.1`로 확정됐다. 릴리스 후 워크플로(버전 확정, README 갱신, 이슈 닫기, 라벨 동기화)는 모두 성공했다.

## 주의사항

- **템플릿 자체에서는 배포가 실행되지 않는다.** `CLIENT-DEPLOY`가 템플릿 레포를 제외하도록 되어 있어 릴리스는 `skipped`로 끝났다(의도된 동작). 새 교회를 만들 때 가져가는 시점부터 적용된다.
- 이미 만든 교회 레포는 따로 확인한다. 은샘은 이미 같은 방식으로 고쳐져 있다. 새누리는 템플릿과 같은 코드였지만 운영에서는 정상 동작 중이라고 확인되어 고치지 않았다.
- API 주소를 비우고 빌드하면 `rss.xml`·`sitemap.xml`이 서버를 기다리다 60초를 넘겨 실패한다. 이번 변경과 무관하게 원래 그렇고, 손대지 않았다.
